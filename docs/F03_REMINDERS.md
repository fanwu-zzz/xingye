# F03 日程提醒

实现日期：2026-10-26。

## 使用

「我的 → 提醒与通知」已接入正式设置。任务/考试、课程分别开关，默认全部关闭；提前时间支持 5/15/30 分钟快捷选择以及 0—1440 分钟自定义。点击「保存提醒设置」后写入本机数据库；返回、旋转、重启后保留。

首次主动保存启用提醒时，Android 13+ 请求通知权限。拒绝不会丢失设置，也不会反复请求；页面显示通知状态和系统设置入口。日程提醒使用独立通知渠道，渠道被禁用时也显示不可用。

Android 12+ 未开启「闹钟与提醒」访问时，使用普通闹钟降级；页面明确提示可能延后，用户可以主动开启准时提醒，不强制申请。[Android 精确闹钟权限说明](https://developer.android.com/about/versions/14/changes/schedule-exact-alarms)

## 提醒规则

- 以日程的本地日期和开始时间为准，考试同样是开始提醒，不是截止提醒。
- 已完成日程不提醒；恢复待办后重新检查未来提醒。
- 静默时段包含开始、不包含结束，支持 23:00—07:00 等跨午夜区间；启用时不允许起止相同。
- 计划提醒时间位于静默时段时直接跳过；即使原定时间不在静默段，实际送达时进入静默段也跳过，不在静默结束后补发。
- 只补发此前已经排入调度、迟到不超过 10 分钟、且未晚于日程开始后 1 分钟的提醒。新启用开关、新建过去日程或修改提前时间，不补发已经错过的提醒。
- 同一事件的同一次开始时间最多发送一次。改名、改备注、改计划名、修改提前时间、关闭再开启和重复系统广播不会重复发送已发提醒；修改日期或开始时间按新的日程时间重新规划。
- 日程在当前系统时区解释；时区、系统时间、设备重启、应用更新、准时提醒授权变化后重排。已经发送的同一日程不会因时区变化再次发送。
- 静默与开关只影响日程提醒，不影响 F01 的专注结束通知。

## 调度与一致性

Room 版本 7，6→7 只新增 `reminder_settings` 和 `event_reminders`，不修改或清空日历、会话、消息及专注表。后者保存每个事件的提醒时间、发生标识和 PENDING / DELIVERED / MISSED 状态；日程删除时外键级联删除提醒凭据。

手动新增、编辑、删除、完成/恢复、整组删除、AI 计划应用、Excel 同组替换及 F01 完成关联任务，均接入统一重排。课表同组替换改为数据库事务，避免删除后新增失败造成半次导入。Room 观察器同时覆盖日程表变化，后台回调发送前重新读取最新日程与设置。

系统仅保留最近一批提醒的单个 AlarmManager 闹钟，同一时刻的多条提醒在一次回调中领取，随后调度下一批，避免导入大量课程后堆积系统闹钟。使用 RTC_WAKEUP；准时提醒可用时使用 setExactAndAllowWhileIdle，否则 setAndAllowWhileIdle，并处理检查后权限撤销的竞态。[Android 闹钟调度说明](https://developer.android.com/develop/background-work/services/alarms)

写入前排入持久化 JobScheduler 补偿任务，写入后不受页面协程取消影响地重排；提醒启用期间另有周期为 15 分钟的补偿检查，全部关闭时取消该周期任务。补偿任务不代替主闹钟，也不保证严格按 15 分钟执行。调度器限额或厂商异常不会阻止日历写入。无常驻提醒前台服务。

发送凭据事务先提交，再调用系统通知，避免重复广播反复响铃。两者不是原子操作：极端情况下，进程在提交后、发布通知前被终止，可能漏掉该条；选择不自动重发，以保持最多一次。系统强行停止应用、厂商后台限制和普通闹钟延迟也可能导致漏提醒；重新打开应用恢复未来调度，不承诺强制停止期间仍可提醒。

## 通知与返回

锁屏公开版本只显示「StudyPlanner 日程提醒 / 打开应用查看安排」，不含标题和备注。解锁后显示类型、标题、日期和开始时间；备注不进入通知。点击打开当前日程详情，可编辑、完成/恢复或删除；删除或重新导入使旧 ID 失效时显示真实空态。系统返回键或页面返回按钮回到日历。
