# StudyPlanner UI 设计规范：新野兽派

> 风格：Neo-Brutalist / 新野兽派。
> 适用：StudyPlanner 的 Android / Kotlin / Jetpack Compose 界面。
> 产品：AI 对话 → 生成学习计划 → 预览并应用到日历 → 跟踪任务与学习统计。

本文件是本项目 UI 的唯一风格基准。新增页面、布局调整、组件、配色、字体和动效修改前必须完整阅读。根目录 AGENTS.md 提供读取入口；不要复制出第二份设计规范。

本规范替代旧的「奶白 + 杏橙 + 大圆角 + 柔和阴影」方案。design/ 中旧设计图仅用于理解功能、内容和信息层级，不再决定配色、圆角或阴影。2026-10-25 已完成主要页面及共享组件迁移；UI 结构见 docs/UI_REFACTOR.md，功能预览与待实现范围见 docs/FEATURE_BACKLOG.md。

## 1. 设计目标与执行顺序

你是一名熟悉 Android 原生交互和新野兽派的设计开发者。界面应像清晰、有力量的学习工作台：黑色结构线、纸面色块、粗体标题、明确的数字与状态。用户应能快速知道今天学什么、进度如何、下一步做什么。

- 功能与可读性优先，在统一视觉语言内做布局设计，避免堆叠装饰。
- 一个页面只有一个最强视觉焦点和一个主操作，其余区域通过留白、字号和结构线建立层级。
- 先定义主题 token 和共享组件，再应用到页面，禁止每个页面发明一套样式。
- 日历、任务、聊天等工作界面不增加巨型 Hero、宣传口号、定价区或无关插画。
- 以下禁止项优先于示例；无障碍、系统 Insets、键盘与触控要求优先于纯装饰效果。
- 数值使用 Compose 的 dp / sp，不照搬 Tailwind、CSS、JSX，不为换风格引入 WebView 或替换技术栈。

## 2. 绝对禁止

- 组件使用圆角、胶囊或圆形容器：卡片、按钮、标签、输入框、导航、聊天气泡、弹窗均为直角。
- 渐变背景、渐变文字、玻璃态、背景模糊、霓虹光晕和装饰性半透明叠层。
- 灰色、浅色或低透明度描边；所有需要描边的业务组件使用纯黑。
- 使用 Material 默认浮起阴影、模糊投影或 tonalElevation 着色模拟层次。
- 沿用旧杏橙色、深棕色、紫色 AI 入口等局部样式，造成新旧主题混杂。
- 用 alpha 淡化正文、禁用状态或完成状态；用明确的实色、文字和图标表达状态。
- 颜色或透明度渐变、弹簧、回弹、呼吸、持续闪烁、装饰性无限动画。
- 悬停时阴影消失，或按下时仍留着阴影；按下位移小于静止阴影偏移量。
- 非交互卡片伪装成按钮，或每个列表项都使用夸张升起、变色和位移动效。
- 多层带描边、带阴影的卡片互相嵌套；使用单侧彩色粗边作为通用装饰。
- 每个区块都放极小、全大写、宽字距的英文眉题；中文正文加宽字距或强行英文化。
- 直接使用未经适配的 Material 默认圆角 Card、Button、FilterChip、AlertDialog、FAB 或导航指示器。

例外只限必要的图形语义：图标内的圆、图表数据点、原生加载指示器，以及必要的系统模态遮罩。例外不用于把业务组件重新做成圆角或玻璃态。

## 3. 颜色 Token

在 app/src/main/java/com/fanwu/studyplanner/ui/theme/Color.kt 统一维护，下表是目标 token。新色先登记，再在共享组件和页面中引用，禁止在各页面散落新的颜色字面量。

| Token | 色值 | 角色 |
|---|---|---|
| BrutalBlack | #000000 | 主文字、描边、硬阴影、深色底 |
| BrutalWhite | #FFFFFF | 卡片、输入区域、深色底上的文字 |
| BrutalPaper | #FAFAF7 | 页面纸白底色，可复用旧底色数值 |
| BrutalPink | #FF006E | 主 CTA、AI 生成入口、少量关键强调 |
| BrutalLime | #CCFF00 | 完成、成功、学习任务 |
| BrutalCyan | #00D9FF | 信息、课程、用户消息背景 |
| BrutalOrange | #FF9500 | 考试、截止提醒、警示 |
| BrutalYellow | #FFFF00 | 选中日期、选中导航、指针悬停反馈 |
| BrutalMutedText | #454545 | 仅用于纸白/白底上的辅助文字 |
| BrutalDisabled | #E5E5E5 | 禁用或已完成区域实色底，保持黑色描边 |
| BrutalDanger | #B91C1C | 删除、错误；白底红字或红底白字 |

配色纪律：

- 页面以黑、白、纸白为主。一个可见区域以一个主强调色和最多一个辅助强调色为宜；多事件类型的日历与图表可按语义显示多色，不做彩虹式卡片拼盘。
- 所有亮色底使用黑字，包括粉色 CTA。禁止粉底白色小字；禁止彩色底上放灰字。
- 黑底、危险红底使用白字。正文对比度至少 4.5:1，大字至少 3:1；新增组合实际校验，不因属于色板就默认合格。
- 日历语义固定：EXAM → BrutalOrange，CLASS → BrutalCyan，STUDY_TASK → BrutalLime。同时显示类型文字或图标，不只靠颜色区分。
- 完成态：实色灰底 + 勾选图标 +「已完成」文字，必要时标题划线；保留可读性。
- 先迁移引用，再清理旧 OrangePrimary、ApricotOrange、DarkBar、NavDark 和紫色占位 token，不直接删除仍被引用的常量。

## 4. 主题与实现位置

- 应用品牌为「星页」，使用用户选定的 A 方案：星星、展开的书页与青色书签。启动图标采用二次元插画，自适应背景资源 `xingye_launcher_background`（res/values/colors.xml，#001A4D），透明前景保留安全留白，并提供 Android 13+ 单色主题图标；业务页面继续沿用本文件的主题 token。系统桌面的圆形/方圆形遮罩由 Launcher 决定。

- ui/theme/Color.kt：统一颜色。
- ui/theme/Theme.kt：目标为固定浅色、dynamicColor = false、不随系统切换到旧紫色深色方案；显式配置 Material 的前景、背景、outline 和容器色。
- ui/theme/Type.kt：统一字号、字重、行高与字体族，不依赖未配置的默认 Material 字体层级。
- 后续需要时新增 ui/theme/Shape.kt / Spacing.kt 管理形状、边框和间距；新增 ui/components/ 管理按钮、面板、标签、输入框等共享实现。
- 所有业务组件使用 RectangleShape，Material 色调和阴影 elevation 均设为 0.dp，再绘制本规范的黑色描边与硬阴影。
- 保持 Compose、Material 3 和现有页面导航结构；换风格本身不要求新增依赖。

## 5. 边框、硬阴影与交互物理

### 边框

| 对象 | 手机 | 宽屏（可用宽度 ≥ 600dp） |
|---|---|---|
| 主面板、主按钮、弹窗 | 2dp 黑色 | 4dp 黑色 |
| 紧凑标签、日期格、输入框、次级操作 | 2dp 黑色 | 2dp 黑色 |
| 内容分隔线、图表坐标线 | 1dp 黑色 | 1dp 黑色 |

共享分隔线只画一次，避免相邻格子叠成不一致的线宽。不是每个文本和每一层布局都要加框。

### 硬阴影

只允许无模糊、无扩散的实色偏移矩形。Compose 使用共享 Modifier.drawBehind / Canvas 在元素后方画矩形，不用 Modifier.shadow 模拟。

| 用途 | 手机 X/Y 偏移 | 宽屏 X/Y 偏移 |
|---|---|---|
| 紧凑交互块 | 2dp | 4dp |
| 主要可按压控件的静止状态 d | 4dp | 6dp |
| 主面板、统计摘要 | 4dp | 8dp |

- 默认阴影为纯黑，仅重点可交互卡片的指针悬停可用粉色阴影。
- 阴影放在独立外层绘制，内容裁剪在内层；为右、下阴影和焦点框预留空间，不能被父布局、列表或弹窗裁掉。
- 任务密集列表以直角平面和黑色分隔线为主，不给每一行叠大阴影。

### 按钮状态：统一采用「悬停抬起，按下压平」

以静止阴影偏移 d 表示按钮高度。位置均相对同一个静止布局原点，不能把按下位移叠加到 hover 位移上。

| 状态 | 表面位置 | 相对表面的阴影偏移 | 背景与反馈 |
|---|---|---|---|
| 静止 | (0, 0) | (d, d) | 组件角色色 |
| 指针悬停 | (-4dp, -4dp) | (d + 4dp, d + 4dp) | 瞬间切为亮黄，阴影增大 |
| 按下 | (d, d) | 无 | 瞬间压到阴影原位置 |
| 键盘聚焦 | 不改布局 | 保留静止阴影 | 外加 2dp 黑色焦点框，与组件间隔 2dp |
| 禁用 | 不位移 | 无 | 灰色实底、黑字黑框、明确禁用语义 |

- pressed 优先于 hovered，禁用时忽略所有升起和按压效果。
- 用 Compose 交互状态驱动共享组件；移动端依赖触摸按压反馈，不能把功能或状态只放在 hover。
- 点击命中区保持稳定，使用绘制/图层位移改变视觉表面，避免按压导致布局跳动或命中区跟着移动。
- 普通文本链接和导航项以背景色块、下划线或边框表达状态，不必全部套用立体按钮效果。

### 动效

- 悬停与释放的位置、硬阴影偏移过渡：150ms、ease-out；颜色切换、按下与移除阴影：0ms。
- 不使用包含颜色/透明度的通用过渡，不使用弹簧或回弹。
- 尊重系统动画缩放/减少动态效果设置，关闭动画时所有状态即时切换，操作结果仍清楚可见。
- AI 生成过程用真实加载状态、文字和取消/重试入口反馈，不用持续闪烁或伪造进度。

## 6. 字体与内容层级

| 内容 | 字号 / 行高 | 字重与字体 |
|---|---|---|
| 页面主标题 | 手机 28/36sp，宽屏 36/44sp | FontWeight.Black / 900，中文无衬线 |
| 区块标题 | 20/28sp，宽屏 24/32sp | 900 |
| 任务、卡片、弹窗标题 | 18/26sp | Bold / 700 |
| 正文、聊天内容、输入文字 | 16/24sp | Normal / 400 |
| 日期、状态、辅助信息 | 14/20sp | Medium / 500 |
| 按钮文字 | 16/24sp | ExtraBold / 800 |
| 统计数字 | 32/40sp，宽屏 40/48sp | Black / 900，数字等宽 |

- 正文以等宽排版气质为目标，优先使用 FontFamily.Monospace；中文回退字体须清晰、字重稳定、混排基线一致。若设备回退造成中文阅读或换行问题，中文长正文使用系统无衬线，时间、日期、数字和短标签保留等宽。
- 不为换风格下载网络字体；不主动引入 Inter / Roboto / Geist 作为新的品牌字体，系统实际字体回退不视为违规。
- 中文不设置 uppercase 和过度 tracking；字距 0，标题可适度紧凑但不能字形重叠。
- 不通过缩小字号解决拥挤；增加换行、留白或改变布局。支持系统字体放大，长标题与按钮文字不被固定高度裁切。
- 聊天正文优先完整显示；任务标题可两行省略，但应能从详情查看全文。宽屏正文限制可读行宽，不横贯整个屏幕。

## 7. 间距与自适应

- 基础间距：4 / 8 / 12 / 16 / 24 / 32dp，优先遵循 8dp 网格。
- 页面水平留白：手机 16dp，宽屏 24–32dp；主区块间距 24–32dp。
- 面板内边距：手机 16dp，宽屏 24dp；列表行间距 12dp；标签内部横向 8dp、纵向 4dp。
- 按钮视觉高度至少 48dp，主 CTA 通常 56dp；采用最小高度而非裁死高度。所有可点击目标至少 48×48dp，小标签与图标可扩大外围命中区。
- 手机单列；可用宽度 ≥ 600dp 后，根据内容采用双栏或约束正文宽度。日历与统计可分栏，聊天文字区域居中限宽，不机械拉伸。
- 正文字号与触控区域不按屏幕宽度减半。宽屏主要增加留白、边框和主面板阴影，不照搬提示词中的所有数值 50% 缩放。
- 处理状态栏、底部手势区与 IME Insets；聊天输入区在键盘上方，底部操作不遮住最后一项内容。
- 以 360dp 手机、常见手机、≥ 600dp 宽屏和系统大字体检查布局，避免意外横向溢出。日历日期条等明确的横向滚动区域可保留。

## 8. 页面与组件范式

### 页面骨架、导航与主操作

- 纸白页面 + 左对齐粗体标题 + 清晰日期/摘要；保留返回键和动作区的原生可达性。
- 顶部栏用黑色底部分隔线界定结构，不增加带圆角的悬浮导航卡。
- 底部保留「日历 / 统计 / 我的」三个入口；使用直角白底、黑色顶边，选中项亮黄色块 + 黑色图标与文字，未选中项黑字白底。取消深棕圆顶栏和圆形指示器。
- 主 CTA 用粉底黑字、黑色粗边、硬阴影，图标和文字表达动作，如「生成学习计划」「应用到日历」。同屏不让多个粉色按钮争夺主次。
- 次操作白底黑字黑框；危险操作使用危险红和明确文字，不能仅靠颜色暗示。
- 图标统一 Material 线性图标或同一组自绘线性图标，约 24dp、2dp 线宽；不要用 emoji 代替产品图标。

### 日历与任务

- 日期条和月历采用直角格子，选中日期亮黄底、黑框、粗体数字；今日用「今」或明确标记，与选中态可区分。
- 事件类型使用统一色板的小色块 + 类型文字；已完成事件使用勾选和文字，不整行降低透明度。
- 任务使用清晰的标题、时间、时长、状态层级；列表可共用一个面板边框，内部用黑色分隔线，避免卡片套卡片。
- 学习任务卡片不显示左侧方形勾选框，也不保留其空白占位；通过左滑或详情中的完成/恢复按钮操作。其他场景的勾选控件仍使用方形，完成操作有即时状态反馈。
- 课程卡片不显示左侧独立的“课”字或勾选符号，不保留图标列占位；课程标签、标题、时间与教室统一左对齐，状态由“已下课”文字表达。
- 课程卡片、详情与编辑界面不显示来源对话名/计划组名；内部仍保留分组关系。学习任务的所属计划名称继续显示。
- 日历展开/收起入口、添加事件、返回今天等动作保持可发现，不靠装饰图案承担点击功能。

### AI 对话与计划预览

- AI 入口为带黑框的粉色或白色直角操作块，取消旧浅紫 chip。
- 会话列表为规整的标题、摘要、时间，不做多层卡片或装饰标签堆积。
- 新建对话选择“导入 Excel 课表”时，名称为空则自动填入“导入课表”，可手动修改；从课表页直接新建和连续新建导入会话时同样适用，不覆盖用户已输入的自定义名称。
- AI 消息白底黑框，用户消息青色底黑字；使用直角和对齐区分角色，不使用圆角气泡。长消息不加大阴影。
- Markdown、代码、表格和计划内容需正常换行与滚动，不能因风格破坏可读性；代码和数据使用等宽。
- 输入区域白底黑框，发送按钮方形；加载时显示「正在生成…」，失败保留输入和重试入口。
- 计划预览以一个面板内的分组和分隔线组织内容，清晰显示计划名、日期范围、任务数和时长。允许改名并核对后，由用户点击「应用到日历」写入，不能生成完自动应用。
- 展示真实空状态、加载、成功、错误、取消和重试状态，不编造计划和统计数字。

### 统计、设置与空状态

- 统计页突出真实的完成量/学习时长，最多一个主要彩色摘要面板；数据表与图表用黑色坐标线、实色柱条、明确数值，不引入第三方图表库。
- 图表无数据时显示「暂无学习记录」及可执行下一步，不用假柱状图填满画面。
- 专注空间已实现 F01，不再显示“预览”。配置支持专注/休息自定义时长、可选任务；运行中呈现剩余时间、暂停/继续、结束保存；专注完成后可选完成任务并开始休息。记录显示真实投入和完成/提前结束状态。
- 统计中的“实际专注时长”只使用有效计时片段，排除暂停与休息；与“计划安排时长”“已完成安排”分开表达。通知或准时提醒权限缺失时显示明确提示，不把权限未开启误报为计时失败。
- 提醒与通知已实现 F03，不显示“预览”。任务/考试与课程分别开关，提前分钟和跨午夜静默时段经过校验后保存；顶部呈现真实通知/准时提醒权限状态，底部呈现待提醒数量与下一次时间。通知跳转到对应日程详情，失效 ID 呈现已删除空态。
- F02 学习目标、F04 备份、F05 学期/重复课程、F06 复盘均为真实功能，不显示“功能预览”。目标按生效周保存历史；备份先校验和预览再确认恢复；重复课程先展示受影响次数及重复/冲突；复盘先展示完整摘要和 DeepSeek 目的地，明确同意后才发送，建议仍需预览确认应用。
- 课表使用可横向滚动的周时间网格；重叠课程分列，不互相遮挡，保留可读的按天列表与详情。学期设置入口位于网格之前，不能埋在整周长网格末尾。
- 设置按分组标题和直角行组织；选择与开关可自绘外观，但必须保留可访问角色、选中状态和触控区域。
- 空状态包含一句说明和一个有用操作，例如「今天还没有任务」+「添加任务」，不只有一行浅灰字，也不强制增加大幅插画。

### 输入、弹窗与反馈

- 输入框始终显示黑色描边和明确标签，placeholder 不能替代标签；focus 增加焦点框或小硬阴影，错误同时提供文字。
- 弹窗为白底直角黑框，零 Material elevation；标题和内容清晰分区，按钮稳定可见，长内容独立滚动。普通高度上限约可用空间的 85%，键盘/横屏/大字体情况下保证操作可达。
- 若使用底部面板，顶部也为直角；系统遮罩可用固定透明度，不做装饰性半透明动画。
- 删除计划组、清空等破坏性操作保留明确二次确认；完成/取消完成等轻操作直接反馈。
- AI 生成/导入流程保留明确提交入口与已有确认步骤。纯视觉改造不得擅自删减确认、改变数据流或导航含义。

## 9. 无障碍与反馈底线

- 自定义按钮、方形勾选框和导航必须保留点击角色、可访问名称、选中/禁用/加载状态；图标按钮提供中文说明，装饰图标不重复朗读。
- 键盘焦点清晰可见，不能简单清除默认焦点而不提供替代；外接键盘与 TalkBack 均可操作关键流程。
- 对比度、48dp 点击目标、系统大字体与减少动态效果是验收项，不能用风格要求排除这些检查。
- 状态始终有文字、形状或图标辅助，不只依赖颜色、悬停或动画。

## 10. 修改 UI 的标准流程

1. 读取本文件，查看相关页面、主题和已有共享组件；旧设计图仅作结构参考。
2. 明确页面的主内容、主操作、信息层级和真实数据状态，再设计布局。
3. 优先完成主题 token 和共享组件；新增或修改 token 同步登记到本文件。现有页面逐页迁移，避免只换颜色却保留旧圆角与阴影。
4. 实现静止、按下、聚焦、禁用、加载、空态和错误态；支持指针时再实现 hover。
5. 涉及 Kotlin / Compose 代码时运行 .\gradlew.bat assembleDebug，再在可用模拟器/真机或 Compose 预览中检查手机、宽屏与大字体。
6. 视觉验收必须看实际渲染。若联想模拟器 screencap 白屏，优先使用可见模拟器窗口、Android Studio 预览或可用真机；uiautomator dump 仅辅助检查文本与结构，不能代替配色、阴影和布局的视觉确认。渲染不可用时如实说明未完成的验证。
7. 仅修改 Markdown 规范时检查内容、链接、规则冲突和 diff，无需编译或安装应用。
8. 保留与本次任务无关的用户修改，避免为视觉重构改变数据库、AI 请求或业务行为。
